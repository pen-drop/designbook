# Extend Designbook

Project configuration selects which installed skills contribute work. An extension adds tasks or blueprints. Rules stay hard constraints.

This area is the handbook's technical teaching path:

1. [How extensions work](/extend/how-extensions-work)
2. [Project configuration](/extend/configuration)
3. [Add an extension](/extend/add-an-extension)
4. [Extend a skill](/extend/extend-a-skill)
5. [Workflows and stages](/extend/workflows-and-stages)
6. [Test an extension](/extend/test-an-extension)

The causal chain is: config → discovered skills and selected integration → matching workflow and stage contributions → artifact → validation. Config does not invent tasks or overwrite hard rules.

Tasks state what to produce. Blueprints are starting points you may replace. Hard rules cannot be overridden. GAIA is the exception: it ships workflow-step prose, not debo task files. [Integrations](/integrations/) explain each product surface; this area owns the enablement procedure.
