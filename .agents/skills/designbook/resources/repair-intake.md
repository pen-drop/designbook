# Repair intake

1. Receive the complete issue list and completed check path. Group all issues by affected artifact; resolve each file/component/entity target and its dependency order. Completion: every issue is assigned to a concrete correction target or explicitly identified as blocked.
2. Discover `repair` for design targets or `repair-config` for backend configuration targets, then load the relevant planning blocks and follow the [shared builder](workflow-building.md). Include one concrete correction task per target with all its issue IDs in parameters. If a recheck is useful, declare its captures and comparisons now, after the known correction tasks. Reuse the original published reference revision and its exact frozen subject/view/state query; bind `reference_query` on each comparison. Bind `actual_path` to the predecessor capture output path. Source captures use their recorded paths, never an inferred breakpoint filename. Completion: the complete repair definition covers all issues and embeds its rules and result contracts.
3. Invoke `execute-workflow <repair-path>`. Report the corrections and remaining recheck findings. Completion: the repair is done or resumably blocked. Recheck findings are results and never add tasks or automatically start another repair.
