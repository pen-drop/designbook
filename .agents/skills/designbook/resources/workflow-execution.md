# Execute a saved workflow

Input: a path to a complete workflow document. This is the sole owner of the task loop.

1. Read `npx storybook-addon-designbook workflow read <path>`. The CLI validates the fixed definition. Completion: a valid document with its current task states is loaded. An invalid document starts no tasks.
2. Choose an unfinished task whose declared dependencies are done. Load `workflow instructions <path> --task <id>` for its saved instructions, context, schemas, config and predecessor results. Treat source paths as provenance. Read project code and input artifacts as needed; use only embedded workflow instructions and rule selection. Completion: the task's entire prescribed context is loaded.
3. Run `workflow start <path> --task <id>`. Execute that task. When context isolation helps, delegate only this existing task and its path/ID to a fresh subagent; it loads the same saved slice. Parallelize only independent declared tasks. Completion: the task's declared outputs are ready for validation.
4. Write the output values as a JSON object and run `workflow done <path> --task <id> --data-file <results.json>`. For direct file outputs, write the declared paths and submit `{}` if there are no data outputs. The CLI validates required results, embedded schemas and declared file validators before marking done. Completion: the CLI confirms task status `done`.
5. On validation failure the task reopens; the CLI refuses the next `start` and every resubmission until a corrective action is recorded. Inspect findings, correct the same task's output, record the action with `workflow start <path> --task <id> --correction <action>`, and submit again. If a concrete blockade persists after an attempted correction, run `workflow block <path> --task <id> --reason <reason> --correction <attempted-action>` and report it. Resume that same document/task with a new corrective action when the missing input or condition changes. Completion: a valid result or a recorded blockade; repeated identical attempts without new action are not progress.
6. Repeat for the fixed pending tasks. Completion: all declared tasks are done, or execution stops at a recorded blockade. Read `workflow summary <path>` and report the result.

Discovery, template loading, rule selection, adding tasks and follow-up workflow creation belong to intake, never this loop. A verification intake may receive the completed check's results and plan a separate repair after this executor returns.
